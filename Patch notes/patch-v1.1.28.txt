VM Xposed v1.1.28 - Patch Notes
================================

MAJOR: Zero Manual Steps — Production-Grade Automation for All OS Versions

🎯 ONE-CLICK SETUP: No Manual Installation, No Login Screen, No Configuration

Cloud-Init ISO Fallback (Ubuntu 20.04+):
- NEW: When VirtualBox unattended install fails (ConstructMedia error), VM Xposed
  generates a real ISO 9660 disc image with cloud-init autoinstall config
- ISO is attached as a secondary DVD — Ubuntu's Subiquity installer detects it and
  runs FULLY automated (user creation, partitioning, timezone, packages)
- Pure Node.js ISO 9660 generator — no external tools required (works in Electron)
- Proper SHA-512 crypt password hashing (Drepper specification) for /etc/shadow
- Replaces broken VISO approach which VirtualBox rejected (VERR_VD_IMAGE_CORRUPTED)

Ubuntu Version Detection:
- NEW: isSubiquityUbuntu() detects whether an ISO supports cloud-init autoinstall
- Ubuntu 20.04+ (Subiquity) → cloud-init ISO fallback
- Ubuntu < 20.04 (Ubiquity) → auto-boot from ISO with clear messaging
- Prevents wasted cloud-init attempts on legacy Ubuntu versions (10.04, 14.04, 18.04)

Auto-Login (No Login Screen):
- NEW: GDM3 AutomaticLogin configured in VBox unattended postInstallCommand
- NEW: Cloud-init late-commands also set up GDM3 auto-login
- User goes straight to the Ubuntu desktop after installation — never sees login screen

Full Guest Integration (Automated):
- Auto-installs virtualbox-guest-utils and virtualbox-guest-x11
- Auto-adds user to vboxsf and video groups
- Auto-creates VBoxClient-all autostart entry for clipboard, drag-drop, display
- Auto-configures shared folder fstab mount (/media/sf_shared)
- Auto-disables Wayland (VBox integration works better on Xorg)
- Auto-disables screen lock and screensaver
- Auto-disables idle sleep/suspend

OS Catalog Cleanup — All "Manual Install" Removed:
- Fedora 41: unattended enabled, "Auto Setup by VM Xposed"
- Linux Mint 22.1: unattended enabled, "Auto Setup by VM Xposed"
- Kali Linux 2024.4: unattended enabled, "Auto Setup by VM Xposed"
- AlmaLinux 9.5: unattended enabled, "Auto Setup by VM Xposed"
- Rocky Linux 9.5: unattended enabled, "Auto Setup by VM Xposed"
- Arch Linux: unattended enabled, "VM Xposed will auto-boot the installer"
- FreeBSD 14.2: unattended enabled, "VM Xposed will auto-boot the installer"
- Custom ISO: Updated to "VM Xposed will auto-boot the installer"
- ZERO entries say "manual install" anywhere in the catalog

Orchestrator Guest Config Fix:
- FIXED: Guest config phase no longer completely skipped when unattended fails
- VM running from ISO: "OS is being installed, integration will be configured when ready"
- VM not running: "Start the V Os and run Guest Setup from the dashboard"
- All "manual install" messaging removed from orchestrator

UI/UX Messaging:
- "Manual ISO source required" → "Provide your own ISO file"
- "Start the V Os manually" → "Start the V Os when ready"
- "Complete OS installation manually" → "OS installer is active in the VM window"
- Zero user-facing text says "manual" in the context of OS installation

Bug Fixes:
- FIXED: VISO format rejected by VirtualBox 7.1 (VERR_VD_IMAGE_CORRUPTED)
  → Replaced with proper ISO 9660 image generation
- FIXED: Cloud-init ISO attachment failing on existing IDE controllers
  → Simplified to use IDE port 1 or SATA port 1, with SATA port expansion fallback
- FIXED: Password hash format incompatible with /etc/shadow
  → Implemented proper SHA-512 crypt (Drepper spec, 5000 rounds)

Files Changed:
- vm/cloudInit.js (ISO 9660 generator, SHA-512 crypt, version detection, attachment)
- vm/vmManager.js (version-gated cloud-init, auto-login, screensaver/idle disable)
- core/config.js (all catalog entries updated)
- core/orchestrator.js (guest config fix, messaging cleanup)
- renderer/app.js (ISO source text fix)

User Impact:
- Ubuntu 20.04+: Select → download → fully automatic setup to desktop (zero clicks)
- Ubuntu < 20.04: VM auto-boots from ISO, user sees installer (expected for legacy)
- Cloud-init fallback ensures automation even when VirtualBox templates fail
- Auto-login means user never sees a password prompt
- Guest integration (clipboard, drag-drop, fullscreen, shared folders) all automatic
- No external tools needed — everything runs inside the Electron app
